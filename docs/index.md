# SonarQube Provider

Manages [SonarQube Server](https://www.sonarsource.com/products/sonarqube/) and
SonarQube Community Build: projects, quality gates and profiles, rules,
permissions, users and groups, DevOps platform integrations, applications,
portfolios, settings, webhooks and email notifications.

## Example usage

```terraform
terraform {
  required_providers {
    sonarqube = {
      source = "muratcanozdemir/sonarqube"
    }
  }
}

# Token authentication (recommended). host and token can also come from the
# SONAR_HOST and SONAR_TOKEN environment variables.
provider "sonarqube" {
  host  = "https://sonarqube.example.com"
  token = var.sonarqube_token
}

variable "sonarqube_token" {
  type      = string
  sensitive = true
}
```

## Authentication

Use a token (`token` or `SONAR_TOKEN`) of a user with the permissions the
configuration needs, usually *Administer System*. Basic authentication
(`user` and `pass`) is supported for servers that still allow it.

To keep secrets out of state, use the write-only arguments (Terraform 1.11 or
later): `password_wo` on `sonarqube_user`, `value_wo` on
`sonarqube_secured_setting`, `secret_wo` on `sonarqube_webhook`, and the
`*_wo` credentials of the DevOps platform settings (`sonarqube_alm_*`) and of
`sonarqube_email_configuration`. Use
the `sonarqube_user_token` ephemeral resource for short-lived tokens.

## Import, query and actions

- **Resource identity** (Terraform 1.12+): projects, quality profiles and
  gates, users, groups, permission templates, applications and their
  branches, portfolios, DevOps platform settings and the email configuration
  can be imported with `import { identity = { ... } }` instead of an ID
  string.
- **List resources** (Terraform 1.14+): `terraform query` finds existing
  projects, quality profiles, quality gates, groups and users, and
  `-generate-config-out` writes their configuration and import blocks.
- **Actions** (Terraform 1.14+): `sonarqube_send_test_email` checks the SMTP
  settings, and `sonarqube_apply_permission_template` applies a permission
  template to existing projects. Run them with `terraform apply -invoke` or
  from a resource's `action_trigger`.

## Editions and versions

Some resources need a commercial edition: applications and pull request
decoration (bindings) need the Developer edition, portfolios the Enterprise
edition. The provider detects the server's version and edition on first use
and rejects unsupported configurations at plan time, before anything is
changed. Set `installed_version` and `installed_edition` to skip detection,
for example when the token cannot read server information.

The acceptance tests run against SonarQube Community Build and the Enterprise
edition of SonarQube Server.

## Concurrency

Terraform applies independent resources in parallel. SonarQube does not
coordinate concurrent changes to the quality profile hierarchy, and
concurrent parent changes, rule activations and profile deletions can
deadlock on the server. The provider therefore serializes those operations
within a run, and serializes changes to the same settings component and the
same quality gate. Other operations run in parallel, subject to
`max_requests_per_second`.

## Schema

### Optional

- `anonymize_user_on_delete` (Boolean) Anonymize users when they are destroyed, in addition to deactivating them. Defaults to `false`.
- `host` (String) SonarQube base URL, e.g. `https://sonar.example.com` or `http://localhost:9000/sonar`. Falls back to `SONAR_HOST`, `SONARQUBE_HOST` or `SONAR_HOST_URL`.
- `http_proxy` (String) Proxy URL. When unset, the standard `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` variables apply.
- `installed_edition` (String) Server edition (`community`, `developer`, `enterprise`, `datacenter`). Skips edition detection. Falls back to `INSTALLED_EDITION`.
- `installed_version` (String) Server version, e.g. `2026.1` or `26.11`. Skips version detection. Falls back to `INSTALLED_VERSION`.
- `max_requests_per_second` (Number) Client-side rate limit shared by all operations of this provider instance. Defaults to `20`. `0` disables it.
- `max_retries` (Number) Retries for throttled (429) requests, and for idempotent requests that fail with 502/503/504 or a connection error. Non-idempotent requests are never replayed after the server may have processed them. Defaults to `3`.
- `pass` (String, Sensitive) Password for basic authentication. Falls back to `SONAR_PASS` or `SONARQUBE_PASS`. Requires `user`.
- `request_timeout` (String) Timeout of a single HTTP request, as a Go duration. Defaults to `60s`.
- `tls_ca_certificate` (String) PEM-encoded CA certificate(s) to trust in addition to the system pool, for servers behind a private CA.
- `tls_insecure_skip_verify` (Boolean) Skip TLS certificate verification. Only for local testing.
- `token` (String, Sensitive) User token. Falls back to `SONAR_TOKEN` or `SONARQUBE_TOKEN`. Conflicts with `user`/`pass`.
- `user` (String) Login for basic authentication. Falls back to `SONAR_USER` or `SONARQUBE_USER`. Requires `pass`.
